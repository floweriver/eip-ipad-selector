# 資料層設計（Data Layer）

> v1.0.0 | 2026-07-16 | 初版：Supabase schema 定案（9 張表）

## 功能說明

把舊版 GAS + Google Sheet 的資料，重建為 Supabase / PostgreSQL 的關聯式資料表。
核心目標：拿掉舊版「`!` 排除 + group 字串展開」的字串魔法，改用乾淨的關聯表；
並把「Apple 原廠 vs eiP 省多少」的比價功能常駐化。

---

## 資料表總覽（共 9 張）

| 資料表 | 白話：這張在存什麼 | 對應舊 Sheet |
|--------|-------------------|-------------|
| `ipad_series` | iPad 四大系列（iPad / Air / Pro / mini）＋系列圖 | codeTable(ipad_option) |
| `ipad_models` | 每個具體型號，含尺寸（11吋/13吋各一台） | codeTable(ipad_description) |
| `sn_codes` | A 碼對照（A1234 → 哪台），給「不知道型號」查詢用 | codeTable(SN) |
| `compat_groups` | 相容群組（依機身尺寸分群，上架時一鍵套用） | codeTable(group_name) |
| `categories` | 產品分類（包/保護殼/鍵盤/類紙膜/觸控筆） | Tabs |
| `products` | eiP 產品：名稱、價格、排名、圖片、連結 | productInfo |
| `product_compatibility` | eiP 產品 ↔ 型號 的相容對照（一台一台記） | productInfo(compatible) |
| `apple_products` | Apple 原廠品項＋價格（比價用） | Appleproductinfo |
| `apple_product_compatibility` | Apple 品項 ↔ 型號 的相容對照 | Appleproductinfo(compatible) |

**不做**：`bts_options`（BTS 方案）、`bns_activities`（BTS 活動圖）— 屬 BTS 限定，已決定移除。

## 各表欄位

### ipad_series（iPad 系列）
- `id` (uuid, PK)
- `name` (text) — iPad / iPad Air / iPad Pro / iPad mini
- `image_url` (text) — 系列圖（取代舊版 Script Properties）
- `sort_order` (int)

### ipad_models（具體型號）
- `id` (uuid, PK)
- `series_id` (uuid, FK → ipad_series)
- `group_id` (uuid, FK → compat_groups) — 屬於哪個相容群組
- `model_name` (text) — 例：`iPad Air 11 吋 (M4)`（尺寸寫進名稱，比照 Apple 官方）
- `is_active` (boolean) — 是否在前台顯示（配件客常有舊機，預設全顯示）
- `sort_order` (int)

### sn_codes（A 碼對照）
- `id` (uuid, PK)
- `model_id` (uuid, FK → ipad_models)
- `sn` (text) — 例：`A2902`

### compat_groups（相容群組）★ 重點
- `id` (uuid, PK)
- `name` (text) — 好記顯示名，例：`舊 11吋通用`
- `legacy_code` (text) — 舊代碼備查，例：`Group_ipadairpro11`
- `sort_order` (int)

### categories（產品分類）
- `id` (uuid, PK)
- `name` (text) — 包 / 保護殼 / 鍵盤 / 類紙膜 / 觸控筆
- `sort_order` (int)

### products（eiP 產品）
- `id` (uuid, PK)
- `category_id` (uuid, FK → categories)
- `name` (text)
- `ranking` (int, nullable) — 有值＝顯示「推薦」徽章；空＝一般
- `price` (int) — 存整數，杜絕舊版字串/數字混用
- `ean` (text, nullable) — 條碼（內部對品用）
- `image_link` (text)
- `website_link` (text)
- `shopee_link` (text, nullable)

### product_compatibility（eiP 相容對照）
- `product_id` (uuid, FK → products)
- `model_id` (uuid, FK → ipad_models)
- 一筆 = 一個「產品配一台」。取代舊版 `!排除`/group 字串。

### apple_products（Apple 原廠品項）
- `id` (uuid, PK)
- `category_id` (uuid, FK → categories)
- `name` (text) — 例：Magic Keyboard
- `price` (int) — 原廠價，用來算「省多少」

### apple_product_compatibility（Apple 相容對照）
- `apple_product_id` (uuid, FK → apple_products)
- `model_id` (uuid, FK → ipad_models)

## 相容群組怎麼運作（最重要的觀念）

**群組 = 上架時的「一鍵套用」按鈕；存進去的仍是一台一台的相容。**

流程：後台新增產品 → 點選相容群組（例「舊 11吋通用」）→ 系統自動把該群所有型號
寫入 `product_compatibility` → 若有例外，當場取消勾那一台。
好處：上架快 + 資料乾淨 + 例外可調 + 不再需要 `!` 排除語法。

## 比價功能（省多少）如何算

選定某台 iPad 後：
1. 撈該型號相容的 eiP 產品（依 category 分好）
2. 撈該型號相容的 Apple 原廠品項（依 category 分好）
3. 呈現：每個分類取 eiP 最低價 vs Apple 最低價 → 算「這類省 X 元」→ 加總「整套省 Y 元」
4. 亦可展開「列出所有可能」讓客人自選

註：省多少為即時計算，不另存欄位。schema 同時支援「取最低」與「列出全部」兩種呈現。

## 重要決策記錄

| 決策 | 原因 | 排除的方案 |
|------|------|-----------|
| 相容性改乾淨關聯表（product ↔ model） | 拿掉舊版字串展開/`!`排除，易錯難維護 | 沿用 group 字串 + `!` 語法 |
| 保留相容群組，但當「一鍵套用」helper | 上架快、資料仍乾淨、例外可調 | 純 product↔group（無法處理例外） |
| 型號比照 Apple 官方，尺寸寫進 model_name | 配件認尺寸，11/13吋須分開 | 11/13吋合併為一台 |
| 比價功能常駐化（非 BTS 限定） | 「省多少」是最強銷售點，全年可用 | 只在 BTS 期間顯示 |
| price 存 int | 舊版字串/數字混用導致計算錯誤 | 沿用 text |
| 不做 bts_options / bns_activities | BTS 限定、活動性質，結束即無用 | 全部照搬舊 BTS 版 |

## 已知地雷 ⚠️

- 舊 codeTable 部分 group_name 命名與內容對不上（`Group_ipadairproold` 實為 mini 6、`Group_iPad69` 混 iPad6+mini5）→ 正名時須釐清，勿直接沿用代碼。
- 舊版一般版與 BTS 版曾大量複製貼上 → 新版務必單一 codebase，勿分兩套。
- `product_compatibility` 必須存「型號層級」，群組只是輸入輔助；勿把相容性直接綁在群組上，否則無法處理單機例外。
- 型號 `model_name` 一旦客人端顯示，改名會影響對照 → 命名一次定好。
