# 資料層設計（Data Layer）

> v1.1.0 | 2026-07-17 | 舊資料匯入完成：9 張表全數落地、總驗證 14 項全綠

## 功能說明

把舊版 GAS + Google Sheet 的資料，重建為 Supabase / PostgreSQL 的關聯式資料表。
核心目標：拿掉舊版「`!` 排除 + group 字串展開」的字串魔法，改用乾淨的關聯表；
並把「Apple 原廠 vs eiP 省多少」的比價功能常駐化。

## 各表欄位

### ipad_series（iPad 系列）
- `id` (uuid, PK)
- `name` (text) — iPad / iPad Air / iPad Pro / iPad mini
- `image_url` (text) — 系列圖（取自舊 config，mini 圖已修正）
- `sort_order` (int)

### ipad_models（具體型號）
- `id` (uuid, PK)
- `series_id` (uuid, FK → ipad_series)
- `group_id` (uuid, FK → compat_groups) — 屬於哪個相容群組
- `model_name` (text, unique) — 例：`iPad Air 11 吋 (M4)`（尺寸寫進名稱，比照 Apple 官方）
- `is_active` (boolean) — 是否在前台顯示（匯入時全部 true）
- `sort_order` (int) — 系列內新機在前、11 吋在 13 吋前

### sn_codes（A 碼對照）
- `id` (uuid, PK)
- `model_id` (uuid, FK → ipad_models)
- `sn` (text, unique) — 例：`A2902`

### compat_groups（相容群組）★ 重點
- `id` (uuid, PK)
- `name` (text) — 好記顯示名，例：`舊 11吋通用`
- `legacy_code` (text, unique) — 舊代碼備查，例：`Group_ipadairpro11`
- `sort_order` (int)

### categories（產品分類）
- `id` (uuid, PK)
- `name` (text, unique) — 鍵盤 / 觸控筆 / 保護殼 / 類紙膜 / 包（照舊版推薦頁籤順序）
- `sort_order` (int)

### products（eiP 產品）
- `id` (uuid, PK)
- `category_id` (uuid, FK → categories)
- `name` (text) — 顯示名；同名多筆＝同產品的不同尺寸規格（相容機型互不重疊）
- `ranking` (int, nullable) — 有值＝顯示「推薦」徽章；空＝一般
- `price` (int) — 存整數
- `ean` (text, nullable) — 條碼；多條碼以逗號分隔
- `image_link` (text)
- `website_link` (text, unique) — lihi 短網址（帶流量追蹤）；HyperKeys 系列無短網址、放官網連結
- `original_link` (text, nullable) — **v1.1.0 新增**：官網原始連結（與短網址並存）
- `shopee_link` (text, nullable)

### product_compatibility（eiP 相容對照）
- `product_id` (uuid, FK → products)
- `model_id` (uuid, FK → ipad_models)
- (product_id, model_id) 唯一。一筆 = 一個「產品配一台」。取代舊版 `!排除`/group 字串。

### apple_products（Apple 原廠品項）
- `id` (uuid, PK)
- `category_id` (uuid, FK → categories)
- `name` (text, unique) — 例：巧控鍵盤 Air 11
- `price` (int) — 原廠價，用來算「省多少」

### apple_product_compatibility（Apple 相容對照）
- `apple_product_id` (uuid, FK → apple_products)
- `model_id` (uuid, FK → ipad_models)
- (apple_product_id, model_id) 唯一

## 相容群組怎麼運作（最重要的觀念）

**群組 = 上架時的「一鍵套用」按鈕；存進去的仍是一台一台的相容。**

流程：後台新增產品 → 點選相容群組（例「舊 11吋通用」）→ 系統自動把該群所有型號
寫入 `product_compatibility` → 若有例外，當場取消勾那一台。

## 比價功能（省多少）如何算

選定某台 iPad 後：
1. 撈該型號相容的 eiP 產品（依 category 分好）
2. 撈該型號相容的 Apple 原廠品項（依 category 分好）
3. 呈現：每個分類取 eiP 最低價 vs Apple 最低價 → 算「這類省 X 元」→ 加總「整套省 Y 元」
4. 亦可展開「列出所有可能」讓客人自選

註：省多少為即時計算，不另存欄位。目前 Apple 品項只涵蓋較新機型（M 系列、
iPad 10/11 世代），舊機的原廠對照品項待後台補齊後比價才完整。

### 重要決策記錄

| 決策 | 原因 | 排除的方案 |
|------|------|-----------|
| 相容性改乾淨關聯表（product ↔ model） | 拿掉舊版字串展開/`!`排除，易錯難維護 | 沿用 group 字串 + `!` 語法 |
| 保留相容群組，但當「一鍵套用」helper | 上架快、資料仍乾淨、例外可調 | 純 product↔group（無法處理例外） |
| 型號比照 Apple 官方，尺寸寫進 model_name | 配件認尺寸，11/13吋須分開 | 11/13吋合併為一台 |
| 比價功能常駐化（非 BTS 限定） | 「省多少」是最強銷售點，全年可用 | 只在 BTS 期間顯示 |
| price 存 int | 舊版字串/數字混用導致計算錯誤 | 沿用 text |
| 不做 bts_options / bns_activities | BTS 限定、活動性質，結束即無用 | 全部照搬舊 BTS 版 |
| 同名多列照列匯入（43 筆） | 各尺寸規格有獨立價格與購買連結；同名變體相容機型互不重疊，前台不會重複 | 同名合併（會丟失價差與專屬連結） |
| products 加 `original_link` 欄位 | Fred 要求短網址與官網連結並存 | 只留一種連結 |
| 匯入用 SQL Editor 手動貼（非連接器） | Claude 帳號與同事共用，切換 Supabase 連接器會影響同事用 ERP | 重接連接器、邀請成員 |
| 群組正名：mini 6、iPad 6・mini 5 | 舊代碼名實不符（地雷） | 沿用舊代碼當名稱 |
| OtheriPad 建為空群組備用 | Fred 決定保留位置 | 不建 |
| 封存工作表不匯 | 已下架品，避免與現售品混雜；Excel 留檔可隨時補 | 一併匯入 |

### 已知地雷 ⚠️

- 舊 codeTable 部分 group_name 命名與內容對不上 → **已於匯入時正名**（見群組對照表），舊代碼存於 legacy_code。
