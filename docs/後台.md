# 後台維護介面（Admin）

> v1.0.0 | 2026-07-17 | 初版：五大管理頁 + 密碼門禁，全數完成待驗收

## 功能說明

`/admin` 底下的內部管理介面，中文 UI。負責維護 9 張表的日常資料，
讓相容性維持「型號層級勾選 + 群組一鍵套用」的乾淨模式。

| 頁面 | 路徑 | 功能 |
|------|------|------|
| 登入 | `/admin/login` | 單一密碼（環境變數 `ADMIN_PASSWORD`），通過後發 30 天 cookie |
| eiP 產品 | `/admin/products` | 列表（分類篩選/搜尋/相容台數）、新增、編輯、刪除 |
| 產品編輯 | `/admin/products/[id]` | 全欄位編輯 + 相容機型勾選（依系列分組）+ 群組一鍵套用 |
| Apple 品項 | `/admin/apple` | 同產品模式的簡化版（品名/分類/原廠價/相容勾選） |
| iPad 型號 | `/admin/models` | 逐列編輯名稱/所屬群組/前台顯示開關/排序；新增/刪除（有關聯資料擋刪除） |
| 相容群組 | `/admin/groups` | 改名/排序/新增/刪除（有成員擋刪除）；成員一覽（成員歸屬在型號頁改） |
| A 碼對照 | `/admin/sn` | 搜尋、逐列改所屬型號、新增（格式檢查 A+4 碼）、刪除 |

## 架構

- **門禁**：`proxy.ts`（Next 16 的 middleware 新名）攔 `/admin/*`，
  驗 cookie（密碼的 SHA-256 衍生 token）。登入/登出在 `app/admin/login/`。
- **資料存取**：全部走 server 端（Server Components 讀、Server Actions 寫），
  用 `lib/supabaseAdmin.ts`（service_role）。**沒有任何 client 端直連資料庫**。
- **相容性寫入**：儲存時整批覆寫（先刪該產品全部關聯、再插入勾選清單），
  與畫面所見完全一致，避免增量同步的邊界錯誤。
- 版面：`app/admin/(panel)/layout.tsx` 左側導覽；login 在 route group 外所以沒有導覽。

### 重要決策記錄

| 決策 | 原因 | 排除的方案 |
|------|------|-----------|
| 門禁用單一密碼 + cookie | 一兩人使用，簡單好維護 | Supabase Auth（多帳號，設定較複雜，之後可升級） |
| 寫入全走 Server Actions + service_role | key 不出 server；RLS 不用開放寫入政策 | 前端用 anon key 寫（需開寫入政策，風險高） |
| 相容清單「整批覆寫」 | 與勾選畫面一致、無邊界情況 | 差異比對增量更新（複雜易錯） |
| 型號/群組刪除前檢查關聯 | 防止誤刪造成孤兒資料 | 直接 cascade 刪除 |
| 群組成員歸屬在「型號頁」改 | group_id 在 ipad_models 上，單一事實來源 | 群組頁雙向編輯（同一資料兩處改易混亂） |

### 已知地雷 ⚠️

- `proxy.ts` 是 Next 16 的新慣例（middleware 已棄用改名），勿改回 middleware.ts。
- Next 16：`cookies()`、`params`、`searchParams` 都要 `await`，寫新頁面別漏。
- `lib/supabaseAdmin.ts` 只能在 server 端 import；放進 "use client" 檔案會把 service_role 洩漏到瀏覽器。
- 換後台密碼 = 改 `ADMIN_PASSWORD`（本機 .env.local + Vercel 環境變數兩處），舊 cookie 隨即失效。
- 產品的 `website_link` 有唯一索引，兩個產品填同一條 lihi 連結會存檔失敗（錯誤訊息會顯示）。
- 刪除產品會連相容設定一起刪且無法復原（有 confirm 提示）。
